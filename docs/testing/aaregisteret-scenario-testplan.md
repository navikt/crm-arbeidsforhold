# Aa-registeret: scenario-for-scenario testplan

**Status:** testplan, ikkje utføringsrapport. Alle scenario nedanfor er
**NOT RUN** med mindre det står eksplisitt lokal evidens. Ingen ny
Salesforce-/ekstern integrasjonstest er utført i samband med dokumentet.

Planen bevarer scenario-ID-ane frå
[kjeldekartet](../architecture/arbeidsforhold-kjeldekart-og-teststrategi.md)
og følgjer
[testdatastrategien](aaregisteret-testdata-strategi.md). Eksisterande Flow-
kjeldekart finst i [Flow-katalogen](../architecture/aareg-flow-katalog.md);
detaljert P360-prosedyre finst i
[P360 inngangs- og verifikasjonsplan](../integrations/p360/inngangar-og-verifikasjonsplan.md).

## 1. Status og gjennomføringsrekkjefølgje

| Status         | Tyding                                                                      |
| -------------- | --------------------------------------------------------------------------- |
| `NOT RUN`      | Ingen relevant test er køyrd i denne arbeidsrunden                          |
| `PASS (lokal)` | Lokal test bestod, med eksplisitt avgrensa mock-/komponentomfang            |
| `PASS (org)`   | Må ha fersk, sanert evidens frå eksakt godkjent scratch-org og handling     |
| `FAIL`         | Køyrd test avvik frå eksplisitt akseptansekriterium                         |
| `BLOCKED`      | Konkret manglande eigaravgjerd, miljøføresetnad eller godkjend trygg metode |

Tilrådd rekkjefølgje:

1. Lokale Jest/Apex-testar med mock, utan org- eller nettverkskall.
2. Kjeldekontroll av relevant Flow-, tilgangs- og metadata-binding.
3. Isolert scratch UI-/Flow-test først etter eiga stadfesting av mål og handling.
4. Ekstern kontrakttest først etter separat eigar-/miljøgodkjenning.

Stopp scenarioet ved teknisk feil, ukjend transaksjon eller uventa sideeffekt.
Ikkje trykk submit/retry ein gong til før ein veit om første handling fekk
verknad. P360-, e-post-, SMS- og distribusjonskøar er separate grenser.
